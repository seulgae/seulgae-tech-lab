## 39. 관리자는 회원 등급 3만: 방장 id 예외 제거 (이번 PR)

> 38번(회원 등급·관리자 신청)의 마무리다. 한 편의 글로 묶는 것을 권한다.

**구현**
- 관리자 판단을 **회원 등급 3(관리자)만**으로 줄였다. 관리자실 문, 쿼리 콘솔, 등급 신청 승인이 모두 같은 기준이다.
- 38번에서 안전장치로 남겨 둔 설정 id 예외(`lab.admin.member-ids`, 운영 Compose `LAB_ADMIN_MEMBER_IDS`)를 지웠다. 방장 계정을 먼저 등급 3으로 올린 뒤에 지웠다.
- 운영 문서에 관리자가 아무도 없을 때 DB에서 직접 한 명을 올리는 방법을 적었다.

**주요 소스**
| 파일 | 내용 |
|---|---|
| `backend/.../admin/AdminAccess.java` | 관리자 = 등급 3, 설정 id 제거 |
| `compose.yml`, `deploy/test_compose.py` | 환경 변수 제거, 다시 생기지 않게 검사 |
| `SqlConsoleTest.java`, `LevelServiceTest.java` | 1·2등급은 관리자 아님, 3등급만 관리자 |
| `README.md`, `docs/operations.md` | 로컬·운영에서 관리자 정하는 방법 |

**기술 포인트**
- **안전장치는 순서대로 걷는다**: 새 권한 체계(등급)를 넣을 때 예전 방식(설정 id)을 잠시 같이 두고, 방장 계정을 새 체계로 옮긴 다음 예전 방식을 지웠다. 중간에 관리자가 0명이 되는 순간이 없다.
- **권한의 근거는 한 곳(DB)**: 이제 관리자인지는 `lab.members.level`만 보면 된다. 배포 설정과 DB가 서로 다른 말을 하는 일이 없다.

**확인**
- 백엔드·프론트 테스트, 배포 설정 테스트를 다시 돌렸다(수치는 PR 본문).
- 확인 못 한 것: 운영 반영 후 방장 계정이 등급 3으로 관리자실에 들어가는지는 운영에서 확인이 필요하다.

## 40. 스키마 V11 확장: 폰 앱(할 일·SNS·송금) (PR #65, 확장 단계)

> 41번(I 키 폰과 앱)과 한 편의 글로 묶는 것을 권한다.

**구현**
- `lab.todos`: 회원별 날짜 할 일(제목 40자, 완료 여부).
- `lab.sns_posts`: 회원이 올리는 140자 글. 최근순, 작성자별 인덱스.
- 은행 송금
  - `lab.coin_events.counterpart_id`(상대 회원)를 추가했다.
  - 사유 공통코드 `TRANSFER_OUT`(보냄)·`TRANSFER_IN`(받음)을 넣었다.
  - 거래 내역을 최근순으로 보는 인덱스를 추가했다.
- 배포 도구: migrate-prod 최신 V11, 지원 V1~V11, CI 릴리스 `db_schema` 10..11.

**주요 소스**
| 파일 | 내용 |
|---|---|
| `backend/src/main/resources/db/migration/V11__phone_apps.sql` | 테이블·열·공통코드 |
| `deploy/migrate-prod.py`, `deploy/ops.py`, `deploy/test_*.py`, `.github/workflows/ci.yml` | V11 지원 |
| `docs/operations.md` | V11 절차 |

**기술 포인트**
- **송금은 행 두 개로 남긴다**: 보낸 사람 `-n`(TRANSFER_OUT), 받은 사람 `+n`(TRANSFER_IN)을 남기고 서로를 상대로 적는다. 사람마다 자기 동전 기록만 보면 거래 내역이 된다.
- **확장 단계라 안전하다**: 새 테이블과 기본값 없는 nullable 열뿐이다. 기존 행을 다시 쓰지 않고, 지금 돌아가는 V10 앱에도 영향이 없다.

**확인**
- 배포 테스트(migrate 계획·지원 범위) 로컬 통과. Flyway 적용은 CI 백엔드 테스트(PostgreSQL)에서 확인한다.

**기술 포인트**
- **송금은 한 트랜잭션, 행 두 개**: 보낸 쪽 잔액을 "잔액 + 변동 ≥ 0" 조건의 UPDATE로 먼저 빼고, 실패하면 409로 끝낸다(아무것도 바뀌지 않음). 성공하면 받는 쪽에 더한다. 두 동전 기록은 서로를 상대(`counterpart_id`)로 가리킨다.
- **할 일은 언제나 member_id로 묶는다**: 조회·수정·삭제 SQL 모두 `WHERE id = :id AND member_id = :m`이다. 남의 할 일 id를 알아도 404만 받는다.
- **가짜 인터넷은 데이터만**: 사이트를 제목·단락·목록·링크 블록 배열로 두고 화면은 그것만 그린다. iframe과 외부 요청이 없어 보안 걱정이 없고, 테스트로 "모든 링크가 있는 사이트로 간다"를 확인한다.
- **달력은 순수 함수**: `monthGrid`, `seoulNow`를 화면 밖에 두어 윤년·일요일 시작·한국 시간 자정을 테스트한다.

**트러블슈팅**
- 증상: 새 테스트 파일이 "모듈을 찾을 수 없음"으로 실패했다. → 원인: Node 테스트(`--experimental-strip-types`)는 확장자 없는 TS import를 풀지 못한다. → 해결: 테스트가 불러오는 모듈은 다른 파일처럼 `.ts` 확장자로 import한다.
- 증상: 앱 안 체크박스가 검게 보였다. → 원인: 페이지 전체가 어두운 색 구성이라 기본 컨트롤도 어둡게 그려졌다. → 해결: 밝은 앱 화면에 `color-scheme: light`와 `accent-color`를 줬다.

**확인**
