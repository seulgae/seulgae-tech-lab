## 39. 관리자는 회원 등급 3만: 방장 id 예외 제거 (이번 PR)

> 38번(회원 등급·관리자 신청)의 마무리다. 한 편의 글로 묶는 것을 권한다.

**구현**

- 38번에서 안전장치로 남겨 둔 설정 id 예외(`lab.admin.member-ids`, 운영 Compose `LAB_ADMIN_MEMBER_IDS`)를 지웠다. 방장 계정을 먼저 등급 3으로 올린 뒤에 지웠다.
- 운영 문서에 관리자가 아무도 없을 때 DB에서 직접 한 명을 올리는 방법을 적었다.

**주요 소스**
| 파일 | 내용 |
|---|---|

**확인**

## 42. 관리자인데 관리자실 문이 안 열리던 문제 (PR #67, 수정)

**증상**
- 운영에서 등급 3 회원이 관리자실 문 앞에서 "관리자만 들어갈 수 있어요"를 봤다.
- 서버는 관리자로 인정했다: `/api/auth/me`는 `level: 3, admin: true`, 관리자 API는 200.

**원인**
- 화면은 `useEffect(() => client?.setAdmin(auth.admin), [auth.admin, connection.phase])`로 게임 클라이언트에 관리자 여부를 알렸다.
- 로그인 확인이 게임 클라이언트 생성보다 **먼저** 끝나면, 이 effect가 돌 때 클라이언트가 아직 없었다.
- 그 뒤 `auth.admin`도 연결 단계(`solo`)도 바뀌지 않아 effect가 다시 돌지 않았다. 클라이언트는 기본값(관리자 아님)으로 남았다.
- #50 이후 회의실 밖은 연결이 없어 연결 단계가 바뀌지 않았다. 그래서 회의실을 한 번 다녀오기 전에는 드러나지 않던 경쟁 조건이었다.

**해결**
- `MultiplayerClient`가 만들어질 때 "지금 관리자인지 묻는 함수"(`isAdmin: () => authStore.get().admin`)를 받는다.
- 문을 열 때마다 그 함수로 로그인 상태를 직접 묻는다. 생성 순서와 상관없이 항상 지금 상태를 본다.
- 실제 권한(쿼리 콘솔·승인 API)은 예전처럼 서버가 요청마다 확인한다.

**주요 소스**
| 파일 | 내용 |
|---|---|
| `frontend/src/features/multiplayer/MultiplayerClient.ts` | `isAdmin` 옵션, `canEnter`에서 사용 |
| `frontend/src/components/GameCanvas.tsx` | 클라이언트 생성 때 로그인 상태 연결 |
| `frontend/tests/rooms.test.mjs` | setAdmin 없이도 로그인 상태로 문이 열린다 |

**기술 포인트**
- **"바뀔 때 알려 주기"보다 "필요할 때 묻기"**: 두 객체의 생성 순서가 정해져 있지 않으면 변경 알림(effect)은 놓칠 수 있다. 판단하는 순간에 원본 상태를 읽으면 순서 문제가 사라진다.
- 진단: 브라우저 콘솔에서 `/api/auth/me`, `/api/admin/tables`를 호출해 서버는 관리자로 인정한다는 것을 먼저 확인했다. 그다음 화면 쪽 흐름을 따라가 원인을 좁혔다.

**확인**
- 프론트 테스트·타입 검사·빌드 통과(수치는 PR 본문). 운영 반영 후 새로고침 없이 바로 열리는지 확인이 필요하다.

- **세 줄 + 의자가 600px 안에 들어가게**: 벽(위 64, 아래 576) 사이에 책상(그림 높이 128)과 의자를 세 번 쌓아야 한다. 줄 간격을 170px로 두고 의자를 책상 바닥 42px 아래에 두니, 맨 아래 의자도 벽 안쪽(554)에 들어왔다.
- **파티션은 "보이는 곳"에**: 처음에는 줄 사이 가로 파티션을 넣었는데 다음 줄 모니터에 가려 거의 보이지 않았다. 통로 쪽 세로 칸막이로 바꾸니 위에서 내려다보는 화면에서도 칸막이가 분명히 보인다.
- **픽셀 확인**: 16×24 스프라이트는 화면에서 너무 작아, 브라우저에서 텍스처 캔버스를 글자 격자로 뽑아 얼굴을 확인했다. 안경 테를 검정에서 회색으로 바꿔 얼굴이 까맣게 뭉치지 않게 했다.

**확인**
- 프론트 테스트 140개, 타입 검사, 빌드, 백엔드 테스트 108개(건너뜀 4) 통과
- 로컬 화면에서 카펫 통로, 책상 여섯과 의자 여섯, 파티션, 오른쪽 열 연구원 셋과 이름표를 확인했다. 로컬에는 채용 API가 없어 이름표는 "상태 조회 실패"로 보인다.
