## 28. 멀티플레이는 회의실에서만: 나머지 방은 혼자, 방 이동은 바로 (PR #50)

**블로그 front matter 초안** (Codex가 그대로 쓰거나 다듬는다)
```yaml
---
title: 슬개기술연구소 — 모두와 함께하는 곳은 회의실 하나면 충분했다
date: 2026-11-18
createdAt: 2026-11-18T10:00:00+09:00
tags: WebSocket, Multiplayer, Phaser, Spring Boot, Architecture
summary: 모든 방을 실시간 멀티플레이로 열어 두니 방을 옮길 때마다 서버 왕복을 기다리고 끊김이 잦았다. 멀티플레이를 회의실에만 남기고, 나머지 방은 서버 없이 바로 옮겨 다니게 바꿨다.
category: seulgae-tech-lab
---
```
> createdAt은 대략 시각이다. 실제 시각은 `git log`로 확인한다.

**배경**: 모든 방에서 서버가 위치를 정하는 구조였다.
- 방 이동은 "문 요청 → 서버 확인 → 새 방 목록"을 기다려야 했다(운영 왕복 약 1초, 연결이 흔들리면 더 길다).
- 연결이 흔들리면 어느 방에서든 끊김이 그대로 보였다.
- 그래서 함께 있는 의미가 큰 회의실에만 멀티플레이를 남기기로 했다.

**구현**
- **회의실 밖: 혼자 둘러보기**
  - 시작할 때 서버에 연결하지 않는다. 캐릭터는 원래도 내 화면에서 먼저 움직이고(예측) 서버가 고쳐 주는 구조라, 서버 없이도 그대로 움직인다.
  - 문을 열면 공유 맵의 문 목적지로 바로 옮긴다(서버 왕복 없음). 들어가면 그 방의 스폰에 선다.
  - 의자는 혼자라 바로 앉는다(서버 확인 없음).
  - 상태 줄: "중앙 로비 · 혼자 둘러보는 중 · 회의실에 들어가면 함께해요"
- **회의실: 함께하기**
  - 회의실 문을 열 때 WebSocket에 연결하고, 서버가 회의실 스폰으로 바로 입장시킨다.
  - 연결을 기다리는 동안은 문 앞에 머문다. 15초 안에 연결되지 않으면(정원 초과, 같은 주소의 다른 창 포함) 문을 닫고 로비에 남는다.
  - 회의실을 나가면 연결을 정상 종료(1000)하고 다시 연결하지 않는다. 회의실 채팅 기록도 비운다.
  - 회의실 안에서 연결이 끊기면 혼자 남은 채로 다시 연결을 시도한다.
- **채팅창은 회의실에서만** 보인다.
- **바닥 아이템(버리기·줍기)은 REST로** 옮겼다. 회의실 밖에는 소켓이 없기 때문이다.
  - `GET /api/inventory/ground?room=`, `POST /api/inventory/drop`, `POST /api/inventory/pick`
  - 서버는 내 위치를 모르므로 클라이언트가 알려 주고, 서버는 방 크기 안인지와 줍기 거리(48px)를 확인한다.
- **관제실 CCTV**: 관제실도 혼자 보는 방이 되어, 회의실 참가자 목록을 REST(`GET /api/lobby/feeds`)로 2초마다 읽는다. 관제실을 나오면 멈춘다.
- **서버**
  - 소켓은 회의실로 바로 입장시킨다(두 번째 사람부터 좌우 40px씩 옆에 선다).
  - 소켓의 방 이동 요청은 "회의실에서만 함께 움직여요"로 거절한다.
  - 소켓의 아이템 처리와 관제실 목록 전송은 지웠다. 핸드셰이크의 회원 확인도 더 쓰지 않아 지웠다.

**주요 소스**
| 파일 | 내용 |
|---|---|
| `frontend/src/features/multiplayer/MultiplayerClient.ts` | 혼자 둘러보기 상태, 문 이동, 회의실 연결·종료, 바닥 아이템·CCTV REST |
| `frontend/src/game/scenes/LabLobbyScene.ts` | 방 스폰, 내 위치 전달, 회의실 밖 의자 |
| `frontend/src/components/GameCanvas.tsx`, `features/multiplayer/components/MultiplayerStatus.tsx` | 회의실에서만 채팅창, 상태 문구 |
| `backend/.../websocket/LobbySocketHandler.java`, `domain/LobbyRoom.java` | 회의실 입장, 방 이동 거절, 아이템·목록 전송 제거 |
| `backend/.../multiplayer/lobby/MeetingFeedController.java`, `inventory/InventoryController.java` | CCTV 목록, 바닥 아이템 REST |
| `tests/rooms.test.mjs`, `tests/latency-tolerance.test.mjs`, `LobbySocketTest.java` 외 | 혼자 이동·회의실 연결·연결 실패·REST |

**기술 포인트**
- **서버가 모든 걸 정할 필요는 없다**: 함께 보지 않는 방에서까지 서버가 위치를 정하면 지연만 생긴다. 예측 이동은 그대로 두고 "보정해 줄 서버"만 빼서 바꿀 곳을 줄였다.
- **문 열림 연출 지키기**: 회의실 밖 방 이동을 같은 순간에 알리면, 장면이 문을 열기도 전에 화면을 바꾼다. 다음 틱(`setTimeout 0`)에 알려 문이 열린 뒤 넘어가게 했다.
- **연결 대기 중 끊김은 실패가 아니다**: 회의실 연결을 기다리다 소켓이 끊겨도 바로 포기하지 않는다. 문 앞에서 재시도하다 15초가 지나면 그때 접는다. 입장 전에 끊긴 걸 "방 이동 끝"으로 처리하면 문이 닫힌 뒤 회의실로 튀어 들어가는 문제가 생긴다.

**확인**
- 백엔드 테스트 81개 통과. 새로 고친 테스트:
  - 회의실 바로 입장, 방 이동 거절, CCTV REST
  - 바닥 아이템 REST(비회원 401, 모르는 방 400), 줍기 거리
- 프론트 테스트 115개, 타입 검사 통과. 새로 고친 테스트:
  - 혼자 이동, 회의실 연결·나가기·재연결 안 함
  - 연결 15초 실패, 바닥 아이템·CCTV REST
- DB 없는 로컬 실행에서 화면 확인:
  - 로비·연구실·사무실·오락실을 오갈 때 WebSocket 연결 0개, 채팅창 없음. 상태 줄이 방마다 "혼자 둘러보는 중"으로 바뀌고, 방마다 바닥 목록을 다시 읽는다.
  - 회의실에 들어가면 "회의실 · 함께 1명"과 채팅창이 보인다.
  - 나오면 서버 로그에 `code=1000, reason=Left meeting room`이 남고, 채팅창이 사라진다.
  - 콘솔 오류 없음.
- 확인 못 한 것
  - 운영(Funnel) 경로에서 회의실 연결 대기 시간
  - 두 기기가 회의실에서 만나는 장면(소켓 테스트로만 확인)

## 29. 관제실 → 관리자실: 방장만 들어가는 운영 DB 쿼리 콘솔 (이번 PR)

**블로그 front matter 초안** (Codex가 그대로 쓰거나 다듬는다)
```yaml
---
title: 슬개기술연구소 — 게임 속 관리자실에서 운영 DB에 쿼리를 날린다
date: 2026-11-18
createdAt: 2026-11-18T13:00:00+09:00
tags: Spring Boot, JDBC, PostgreSQL, Security, React
summary: 관제실을 관리자실로 바꾸고, 가운데 슈퍼컴퓨터에서 운영 DB에 SQL을 직접 실행하는 쿼리 콘솔을 만들었다. 방장 회원만 쓸 수 있고, 한 문장·5초·200행 제한과 감사 로그를 붙였다.
category: seulgae-tech-lab
---
```
> createdAt은 대략 시각이다. 실제 시각은 `git log`로 확인한다.

**구현**
- **관리자실**(방 id는 `control-room` 그대로, 이름만 "관리자실")
  - 분위기: 월넛 벽, 버건디 카펫, 금빛 장식, 가죽 의자, 책장.
  - 가운데에 슈퍼컴퓨터 한 대를 두었다. 불빛이 깜박이고 "ADMINISTRATOR · PRODUCTION DB" 문패와 ● LIVE 표시가 있다.
  - CCTV 모니터 월·콘솔과 CCTV 화면(회의실 목록 REST 포함)은 지웠다.
- **방장만 입장**
  - 관리자 회원 id를 서버 설정 `LAB_ADMIN_MEMBER_IDS`(Compose)로 넣는다. IP가 동적이라 IP가 아닌 **로그인 세션의 회원 id**로 판단한다.
  - `/api/auth/me`가 `admin`을 알려 주고, 관리자가 아니면 로비의 관리자실 문 앞에서 "관리자만 들어갈 수 있어요"만 뜬다.
  - 방 이동은 화면에서만 처리하므로 문은 화면 장치일 뿐이다. **진짜 권한은 관리자 API가 요청마다 확인한다**(로그인 안 함 401, 관리자 아님 403).
- **쿼리 콘솔**(슈퍼컴퓨터에서 E)
  - 왼쪽: 앱 DB 계정이 볼 수 있는 **모든 테이블·뷰 이름**(`information_schema.tables`, 시스템 스키마 제외)과 찾기 칸. 누르면 `SELECT * FROM 스키마.테이블 LIMIT 100;`이 들어간다.
  - 오른쪽: SQL 입력, 실행(Ctrl/⌘+Enter), 결과 표(머리글 고정, NULL 표시), "N행 · 12ms" 또는 "N행 변경됨", DB 오류 메시지.
  - 조회가 아닌 쿼리(INSERT·UPDATE·DELETE·TRUNCATE·DROP, 데이터를 바꾸는 WITH, EXPLAIN ANALYZE)는 실행 전에 한 번 더 묻는다.
  - API: `GET /api/admin/tables`, `POST /api/admin/sql`

**안전장치**
- 한 번에 **한 문장**만 실행한다. 끝 세미콜론은 허용하고, 중간에 `;`가 있으면 거절한다.
- 트랜잭션 안에서 `SET LOCAL statement_timeout = '5s'`로 시간을 제한한다. 실패하면 rollback한다.
- 결과는 최대 200행, 칸당 1,000자까지 보여 준다.
- 앱 DB 계정 권한으로 실행된다. 테이블 소유자가 아니라 DDL은 DB가 거절한다.
- 실행한 SQL(500자까지), 회원 id, 걸린 시간, 행 수를 서버 로그에 `[admin-sql]`로 남긴다(감사).

**주요 소스**
| 파일 | 내용 |
|---|---|
| `backend/.../admin/{AdminAccess,SqlConsole,AdminController}.java` | 관리자 확인, SQL 실행·테이블 목록, API·감사 로그 |
| `backend/.../auth/AuthController.java`, `compose.yml` | `admin` 응답, 관리자 회원 id 설정 |
| `frontend/src/features/admin/*` | 쿼리 콘솔 창, 읽기 전용 판별, 테이블 쿼리 |
| `frontend/src/game/rooms/adminRoomFx.ts`, `roomThemes.ts`, `shared/lobby-world.json` | 관리자실 분위기·슈퍼컴퓨터 |
| `frontend/src/features/multiplayer/MultiplayerClient.ts`, `LabLobbyScene.ts` | 관리자실 문 확인, CCTV 목록 제거 |
| `SqlConsoleTest.java`, `tests/admin.test.mjs`, `tests/interaction.test.mjs` 외 | 실행·제한·되돌리기·관리자, 문 확인 |

**기술 포인트**
- **문은 UX, 권한은 서버**: 방 이동이 화면에서만 일어나는 구조(28번)라, 문을 막는 건 보안이 아니다. 관리자 API가 세션 회원 id로 매번 확인한다.
- **`Statement` vs `PreparedStatement`**: `PreparedStatement`는 `?`를 매개변수로 해석한다. 그래서 JSONB `?` 연산자 같은 SQL이 깨진다. 콘솔은 `Statement`로 실행하고, 여러 문장 실행은 세미콜론 검사로 막았다.
- **JDBC 가짜로 테스트**: DB 없는 테스트 환경이라 `java.lang.reflect.Proxy`로 Connection·Statement·ResultSet을 흉내 냈다. 시간 제한 설정, 200행 자르기, 실패 시 rollback을 확인했다.

**트러블슈팅**
- 증상: CI의 API 계약 테스트(`backend/tests/research-api.mjs`)가 실패.
- 원인: `/api/auth/me` 응답을 정확히 비교한다. `admin: false`를 더해 모양이 달라졌다.
- 해결: 기대값에 `admin: false`를 넣었다. 로그인하지 않으면 관리자 API가 401인지도 같은 테스트에서 확인한다.

**확인**
- 백엔드 테스트 84개, 프론트 테스트 119개, 타입 검사, 빌드 통과.
- DB 없는 로컬 실행에서 확인한 것
  - `/api/auth/me`가 `admin:false`를 준다.
  - 로비에 채팅창이 없다.
- 확인 못 한 것
  - 관리자실 화면: 브라우저 창이 숨겨져 있어 캐릭터를 문까지 옮기지 못했다.
  - 실제 PostgreSQL에서의 쿼리 실행: 운영에서 방장 계정으로 확인이 필요하다.
