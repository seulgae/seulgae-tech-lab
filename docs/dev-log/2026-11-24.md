## 72. 은행 적금, 슬개 증권(주식 앱), 오락실 내기 게임 (PR #105, 사용 단계)

> 71번(V20 확장)과 한 편의 글로 묶는 것을 권한다. **V20 마이그레이션 뒤에 머지**한다(릴리스 `db_schema` 20..20).

**구현**
- **적금**(은행 앱 안): 1일 3%, 3일 10%, 7일 25%. 한 번에 1~1000원, 동시에 3개까지. 만기에 찾으면 원금+이자(내림), 만기 전에 찾으면(해지) 원금만 돌려받는다.
- **슬개 증권**(폰 앱, 회원): 가상 종목 6개. 시세는 10분마다 종목별 최대 등락폭(3~25%) 안에서 무작위로 움직이고, 누구에게나 같은 시세가 보인다. 한 번에 1~100주, 하루 30번 거래. 작은 차트(오르면 빨강, 내리면 파랑), 평균 단가와 평가 손익을 보여 준다.
- **오락실 내기 게임**: 위쪽 오락기 네 대가 홀짝(1.9배)·사다리 타기(2.8배)·주사위 맞히기(5.5배)·슬롯머신(7 세 개 50배, 같은 그림 세 개 10배, 두 개는 절반)이다. 한 판 1~20원, 하루 50판. 결과는 서버의 SecureRandom이 정하고 화면은 연출만 한다. 모든 게임은 기대값이 건 돈보다 조금 작다(0.92~0.96, 오락실이 이긴다).

**주요 소스**

| 경로 | 내용 |
| --- | --- |
| `backend/.../savings/service/impl/SavingsServiceImpl.java` | 가입·찾기, "진행 중일 때만 닫기"로 두 번 받기 방지 |
| `backend/.../stock/service/impl/StockServiceImpl.java` | 볼 때 밀린 만큼 시세 따라잡기(낙관적 잠금), 매수·매도, 평균 단가 |
| `backend/.../gamble/service/impl/GambleServiceImpl.java` | 네 게임의 결과·당첨금, 사다리 길 따라가기 |
| `frontend/src/features/phone/apps/SavingsSection.tsx` | 은행 앱 적금 카드 |
| `frontend/src/features/phone/apps/StockApp.tsx` | 주식 앱(목록·차트·거래) |
| `frontend/src/features/arcade/GamblePanel.tsx` | 내기 게임 창(주사위 흔들기, 사다리 길 그리기, 슬롯) |

**기술 포인트**
- 시세는 스케줄러 없이 움직인다. 누군가 볼 때 마지막 변동 시각부터 10분 단위로 밀린 만큼(최대 36번) 무작위 걸음을 만들고, `UPDATE … WHERE updated_at = 읽은 값`으로 한 요청만 반영한다. 나머지 요청은 반영된 값을 다시 읽는다.
- 적금 찾기는 `UPDATE … WHERE closed_at IS NULL`이 성공한 요청만 동전을 받는다. 동시에 두 번 눌러도 한 번만 들어간다.
- 오락실 기대값은 테스트에서 각 게임 20만 판을 돌려 0.85~0.99 범위인지 확인한다.
- 폰 탭 버튼이 밝은 폰 화면에서 안 보이던 문제(흰 테두리)를 고쳤다. 선택한 탭은 금색으로 표시한다.

**확인**

- 프론트 테스트 154개 통과, 타입 검사 통과.
- 로컬 브라우저(로그인과 API 응답은 브라우저에서 가짜로 채움): 사다리 길 그리기와 결과 문구, 주식 앱 목록·차트·종목 상세, 은행 적금 가입과 목록을 확인했다. 실제 서버 응답으로는 운영에서 확인해야 한다.

## 73. 오락실 메인 오락기 게임 고르기, 내기 게임 하루 10판, 스태미나 → 기력 (PR #106)

**구현**
- 메인 오락기에서 E를 누르면 **게임 고르기** 화면이 나온다. 고를 수 있는 게임은 넷이다.
  - **벽돌 부수기**: 원래 있던 게임.
  - **블록 쌓기**: 떨어지는 네 칸 블록으로 가로줄을 채워 지운다. 줄을 지울수록 레벨이 오르고 빨라진다.
  - **지렁이 사과 먹기**: 사과를 먹을수록 길어지고 빨라진다.
  - **하늘 순찰대**: 자동 사격 세로 슈팅. 적기와 적 총알을 피한다.
- 이름과 그림은 장르(블록 퍼즐·스네이크·종스크롤 슈팅)만 따르고 기존 상업 게임의 이름·그림은 쓰지 않았다.
- 새 판을 시작할 때 회원은 벽돌 부수기와 같이 1원(HP -3, 기력 -5)을 내고, 비회원은 무료다. 게임마다 최고 점수는 이 브라우저에 남는다. 터치 기기에서는 화면 버튼(◀▲▼▶ A)이 나온다.
- **내기 게임 하루 10판**: 홀짝·사다리·주사위·슬롯을 합쳐 하루 10판까지만 할 수 있다(이전 50판).
- **기력**: "스태미나"가 화면에서 글자 칸을 넘어가 "기력"으로 바꿨다. 받침이 생겨 조사(을/이/은/으로)도 함께 고쳤다.

| 경로 | 내용 |

| `frontend/src/features/arcade/ArcadePanel.tsx` | 게임 고르기 창 |
| `frontend/src/features/arcade/retroGame.ts` | 새 게임 공통 모양(시작 상태·한 프레임 진행·그리기) |

## 74. 오락실 모든 게임 하루 5판, 남은 판·막힌 이유 안내 (PR #107)

- **문제**: 오락기를 4판 하니 더 못 했다. 원인은 횟수 제한이 아니라 기력이었다. 한 판에 기력 5가 들고 남은 기력이 모자라면 서버가 423을 돌려주는데, 화면에는 "기운이 없어요"만 나와 횟수 제한처럼 보였다.
- **하루 5판**: 메인 오락기 네 게임을 합쳐 하루 5판(6판째 429). `GET /api/inventory/arcade`로 남은 판을 읽는다. 내기 게임 넷도 합쳐 하루 5판(이전 10판).
- **안내**: 창마다 "하루 5판 · 오늘 N판 남음"을 보여 준다. 막힐 때는 이유를 나눠 "오늘 5판을 다 했어요" 또는 "기력이나 HP가 모자라요(한 번에 HP 3·기력 5 필요). 로비 데스크에서 커피·케이크로 채워요"라고 안내한다. 남은 판이 0이면 내기 게임 돌리기 버튼이 꺼진다.

**확인**: 백엔드 테스트 119개(5판 제한 테스트 추가), 프론트 테스트 159개(안내 문구 테스트 추가), 타입 검사 통과. 로컬 브라우저에서 고르기 화면과 게임 화면 안내 문구를 확인했다.

## 76. 서비스 연구실 개편: 내 자리 컴퓨터(메일·아이디어·QA·개발), 연구원 자리 (PR #109, 사용 단계)

> 75번(V21 확장)과 한 편의 글로 묶는 것을 권한다. **V21 마이그레이션 뒤에 머지**한다(릴리스 `db_schema` 21..21).

**구현**
- 예전 업무 게시판 셋(QA → 유지보수 → 운영)을 없앴다. 왼쪽 열 위·가운데 자리에는 연구원이 앉아 일하고, 왼쪽 맨 아래가 **내 자리 컴퓨터**다.
- 내 자리 모니터 바탕화면 아이콘 넷:
  - 📧 **메일**: 연구소장이 보낸 오늘 할 업무. 물고기 낚기, 오락실 한 판, 커피 한 잔, 게시판 글 하나, 자바 문제 하나. 실제로 하면 서버 기록으로 자동 체크되고, 다 하면 동전 5원(하루 한 번).

  - 🐞 **QA 게시판**: 등록 → 조치 중 → 조치 완료로만 진행한다(되돌리기 없음, 로그인한 누구나). 상태별로 걸러 본다.
  - ☕ **개발**: 자바 printf 기초 7문제. `System.out.printf("___", 인자);`의 형식 문자열만 채워 실행하면 서버가 실제 `String.format`으로 출력을 만들어 채점한다. 맞히면 동전 1원(하루 3번).
- 게시판 글 등록·QA 단계 변경은 예전과 같이 HP -3·기력 -5, 동전 10원(하루 10번)이다.

## 77. 커피·음료를 마셔도 기력이 바로 안 오르는 것처럼 보이던 문제 (PR #110, 수정)

- **증상**: 로비 커피나 자판기 음료를 마셔도 기력이 바로 오르지 않는 것 같았다. 확률로 오르는지 묻는 질문이 나왔다.
- **원인**: 확률은 없다. 서버는 커피·음료 +5, 물 +2를 바로 더하고(최대치에서 멈춤), 가득이면 동전을 받지 않고 거절한다. 문제는 보이는 쪽이었다.
  - 페이지를 연 뒤 가방(동전·HP·기력)을 아직 한 번도 읽지 않았으면, 첫 구매 때 "이전 값"을 몰라 캐릭터 위 "기력 +5" 표시가 뜨지 않았다.
  - 기력은 폰 홈 화면에만 보여서, 마셔도 화면에서 바뀌는 게 없었다.
- **수정**:
  - 게임을 시작할 때 가방을 바로 읽는다. 간식을 살 때 아직 안 읽었으면 먼저 읽는다.
  - 로비 커피·케이크 안내 띠와 자판기 안내에 마신 뒤 실제 값(예: "기력 45/50")을 함께 보여 준다. 최대치에 가까우면 +5보다 적게 오른다는 것도 숫자로 보인다.

**확인**: 프론트 테스트 160개 통과(처음 구매에도 가방을 먼저 읽고 기력 +5 변화량을 띄우는지 확인하는 테스트 추가), 타입 검사 통과.

## 78. 내 자리 컴퓨터는 의자에 앉아서 켜기 (PR #111)

- 서비스 연구실 왼쪽 맨 아래 의자(`office-1-chair-2`)에 앉으면 잠깐 뒤 내 자리 모니터가 켜진다.
- 컴퓨터 앞에서 E를 눌러도 먼저 그 의자에 앉힌 뒤 모니터를 켠다. 이미 앉아 있으면 바로 켠다. 창을 닫아도 앉은 채로 있고, E를 다시 누르면 일어난다(의자에서 가장 가까운 대상이 의자일 때).
- 참고: 게시판이 그대로 보인다는 문의는 #109 배포가 끝나기 전이라서였다. 배포가 끝난 뒤에는 새 화면이 나온다.

**확인**: 프론트 테스트·타입 검사 통과. 앉기 흐름은 장면 코드라 운영에서 직접 확인해야 한다.
