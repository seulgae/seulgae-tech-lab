# 로비 자판기·경비원과 사무실 휴게 소품

## 동작

- 로비 왼쪽 책장 자리(x168)를 자판기로 교체했다. 오른쪽 책장은 그대로 책을 읽을 수 있다.
- 자판기 앞에서 E를 누르면 콜라·사이다·환타(각 2원), 물(1원)을 고른다. 로그인 회원의 기존 동전을 사용하고 구매 즉시 마신다. 탄산음료는 스태미나 +5, 물은 +2이며 최대치까지만 회복한다. 별도 아이템으로 쌓이지 않는다.
- 스태미나이 가득하면 422, 잔액 부족은 409, 비회원은 401로 거절한다. 거절된 구매는 차감하지 않는다. 클라이언트는 음료 종류만 보내고 서버가 가격을 결정한다.
- 구매 트랜잭션에서 회원 인벤토리 행을 잠근 뒤 회복 필요 여부를 판단한다. 여러 요청이 동시에 들어와도 먼저 회복을 마친 다음 요청은 가득 찬 상태를 보고 결제를 거절한다. 은행 내역에는 각 음료 이름이 남는다.
- 서비스 사무실 왼쪽 벽에 정수기(x60), 오른쪽 위 구석에 화분(x740)을 두었다. 정수기 앞 E는 무료 물 마시기 연출이며 잔액·HP·스태미나은 바꾸지 않는다. 화분은 기존 흔들기 기능을 사용한다. 가구 충돌은 서버·클라이언트가 같은 공유 맵을 읽는다.
- 로비에는 남색 제복·모자·배지·회색 구레나룻을 가진 경비 아저씨가 순찰한다. 방명록 작성 잔소리를 혼잣말·E 대사로 안내한다.
- 로비 청소 직원은 50px/s, 경비원은 58px/s, 사무실의 야근 연구원은 52px/s, 질문 연구원은 68px/s로 움직인다. 걷기 사이 휴식도 줄였다. 작업석 담당자와 앉았다 일어나는 직원의 기존 동작은 유지한다.

## DB와 적용 순서

자판기 구매 사유는 coin_events의 외래 키를 충족해야 하므로 V14 공통코드가 선행되어야 한다.

1. [DB 준비 PR #77](https://github.com/seulgae/seulgae-tech-lab/pull/77)을 병합하고 13..14 호환 릴리스를 배포한다.
2. 운영 담당자가 기존 명시적 마이그레이션 도구로 백업 후 V14를 적용·검증한다.
3. 이 기능 PR을 병합하고 14..14 호환 릴리스를 배포한다. V13에서는 기존 배포 호환성 검사로 거절된다.

자동 마이그레이션이나 운영 서버 접속은 추가·실행하지 않았다. 자세한 준비 절차는 `docs/vending-schema.md`를 참고한다.

## 검증

로컬 프론트엔드 테스트 147건, 프로덕션 빌드와 린트를 확인했다(기존 경고 3건). 실제 Chrome에서 로비 경비 대사·자판기 E·네 음료 구매·잔액 부족·가득 참·사무실 정수기 E·구석 화분·390px 화면을 확인했다. 이 브라우저 구매 검증은 API 응답을 대체한 UI 검증이다.

로컬 서버 검증 110건 중 105건 통과, CI DB 전용 5건은 조건에 따라 건너뛰었다. 서버 단위 테스트는 네 음료 가격과 회복량, 잔액 부족·가득 참·잘못된 종류에서 무차감을 검증한다. 실제 PostgreSQL 공통코드·구매 내역·동시 결제 잠금은 CI의 고정된 일회용 research_ci DB에서 별도 검증한다. 개발·운영 DB에 검증 데이터를 쓰지 않는다.
