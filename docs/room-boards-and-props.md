# 회의 안건·아이디어 일지·의자·식물·창문·시계

## 회의 안건 (회의실 화이트보드)

- 화이트보드 앞에서 E를 누르면 안건 패널이 열린다. 목록, 작성, 내 안건 수정·삭제를 할 수 있다.
- 제목은 화이트보드 한 줄에 보이는 **8자**, 내용은 **130자**까지다. 글자 수는 서버와 같이 유니코드 코드 포인트로 센다(이모지 1자).
- 화이트보드에는 최근 안건 5개의 제목이 6초마다 돌아가며 보인다. 20초마다 다시 읽고, 이 브라우저에서 안건을 바꾸면 바로 갱신한다.
- API: `GET /api/meeting-agendas?limit&offset`, `POST /api/meeting-agendas`, `PUT|DELETE /api/meeting-agendas/{id}`(`X-Edit-Token`).
- 저장: Flyway V2 `lab.meeting_agendas`. DB 제약으로도 8자·130자를 강제한다.

## 연구 아이디어 일지 (로비 키오스크)

- 연구 기록 패널의 "아이디어 일지 쓰기"를 누르면 제목이 다음 번호 `연구 아이디어 일지 #N`으로 미리 채워진다. 제목은 40자까지 고칠 수 있고, 내용은 **130자**까지다.
- 목록과 상세에서 내 일지에 "내 일지" 표시와 수정·삭제가 나온다.
- 기존 연구 기록 테이블에 저장한다(요약 = 본문 = 내용).
- 다음 번호는 `연구 아이디어 일지 #숫자` 형식 제목 중 가장 큰 번호 + 1이다.
- API: `GET /api/research-records/ideas/next-number`, `POST /api/research-records/ideas`, `PUT|DELETE /api/research-records/{id}`(`X-Edit-Token`).
- 기존 개발 전용 일반 작성 API(`lab.research.write-enabled`)는 그대로 꺼 둔다.

## 로그인 없는 쓰기의 보호

- **수정 키**
  - 글을 만들면 서버가 32바이트 임의 키를 한 번만 돌려준다.
  - DB에는 SHA-256 해시만 저장하고, 비교는 상수 시간으로 한다.
  - 브라우저는 키를 `localStorage`(`lab.editTokens`)에 보관하고, 수정·삭제할 때 `X-Edit-Token` 헤더로 보낸다.
  - 키가 다르면 403, 글이 없으면 404다.
  - 다른 브라우저나 저장소 삭제로 키를 잃으면 그 글은 수정·삭제할 수 없다. DB에서 직접 지워야 한다.
  - V1에서 만든 연구 기록은 해시가 없어 수정·삭제할 수 없다.
- **속도 제한** (`WriteRateLimiter`, 작성·수정·삭제 모두)
  - 접속 주소(`X-Forwarded-For` 첫 값)마다 여유 5회, 12초마다 1회 보충한다.
  - 서버 전체로는 여유 30회, 30초마다 1회 보충한다.
  - 넘으면 429다. CI 통합 검증만 `LAB_WRITE_CLIENT_CAPACITY`로 여유분을 늘린다.
- **입력 검증**: 앞뒤 공백을 지우고, 제목은 한 줄, 줄바꿈·탭 외 제어 문자는 거부한다. 화면은 React 텍스트로만 그리므로 HTML이 실행되지 않는다.
- **알려진 한계**: 로그인과 관리자 화면이 없으므로 운영 중 부적절한 글은 DB에서 직접 지워야 한다. `X-Forwarded-For`는 위조할 수 있지만, 서버 전체 제한이 상한을 둔다.

## 의자 앉기

- 의자는 공유 맵의 `chair` 가구에서 방별 순서로 id를 만든다(`lobby-chair-0`, `meeting-room-chair-1` 등). 서버 `LobbyWorld.seats`와 클라이언트 `roomSeats`가 같은 규칙을 쓴다.
- 의자는 책상·테이블을 바라보므로 **의자 뒤(아래)에서** 다가가 E를 누르면 앉는다. 같은 의자에서 E를 다시 누르거나 이동하면 일어난다.
- **프로토콜**
  - `{"type":"seat","seatId":"lobby-chair-0"|null,"roomEpoch":n}`로 요청한다.
  - 서버는 의자와의 거리(40px), 같은 방, 빈자리를 확인한다.
  - 서버 상태의 플레이어에 `seat`(의자 id 또는 null)가 붙는다.
  - 이동 명령이 처리되거나 방을 옮기면 서버가 자리를 비운다.
- **클라이언트 표시**
  - 확인을 기다리지 않고 먼저 앉은 모습을 보여 준다. 1.5초 안에 서버가 확인하지 않으면 일어난다.
  - 앉은 모습(뒷모습)은 의자 위에 그린다. 서버 좌표와 물리 몸체는 의자 뒤에 그대로 둔다.
  - 다른 참가자의 앉은 모습도 서버 `seat`로 그린다.
- 회의실 의자에 앉으면 **테이블 대화가 자동으로 켜지고**, 일어나면 꺼진다. 앉은 자리도 테이블 범위에 들도록 테이블 대화 범위를 64에서 96px로 넓혔다.

## 식물

- 화분을 클릭(터치)하거나 가까이에서 E를 누르면 화분이 흔들리고 나뭇잎 9장이 떨어진다.
- 흔들리는 동안에는 다시 시작하지 않는다. 각 브라우저에서만 보이는 연출이다.

## 창문과 시계

- **창문**: 로비·회의실 창문 유리 뒤에 현재 시각의 하늘을 그린다(`timeOfDay.ts`, 1분마다 갱신).

  | 시간대 | 시각 | 하늘 |
  |---|---|---|
  | 새벽 | 0~5시 | 남색, 달과 별 |
  | 이른 아침 | 5~8시 | 분홍·주황 지평선, 낮은 해 |
  | 아침 | 8~11시 | 맑은 하늘 |
  | 점심 | 11~16시 | 가장 밝은 하늘, 높은 해 |
  | 노을 | 16~19시 | 보라·주황, 지는 해 |
  | 저녁 | 19~24시 | 어두워지는 남보라, 달과 별 |

  창으로 들어오는 빛의 색·세기도 시간대를 따르고, 밤에는 로비 샹들리에를 더 밝게 한다.
- **시계**: 로비·회의실 벽시계가 브라우저의 현재 시각을 1초마다 가리킨다(시·분·초침). 아래에 `HH:MM`을 표시한다.

## 게시물 목록 페이지 이동 — 2026-11-22

- 회의 안건, 연구 기록, 방명록, QA·유지보수·운영 게시판, 폰 SNS, 채용 목록은 한 목록에 최대 5건을 표시한다.
- 목록 아래에 현재 페이지와 이전·다음 버튼을 둔다. 첫 페이지의 이전과 마지막 페이지의 다음은 비활성화한다.
- 업무 게시판의 처리 대기·기록, 채용의 업무 이력·검토/지원·공고·보고서는 각각 독립적으로 이동한다. 채용 분류를 바꾸면 첫 페이지부터 보여 준다.
- 회의 안건·연구 기록은 기존 limit/offset API를 5건 단위로 사용한다. 다른 목록은 기존 응답을 화면에서 나누며, 서버 조회 상한은 기존 값을 유지한다.
- 새 글 저장 후 첫 페이지로 돌아가고, 조회 중에는 서버 페이지 이동을 막는다. 안건 조회 실패 시 같은 페이지를 다시 요청할 수 있다. 자동 갱신으로 목록이 줄면 표시 가능한 마지막 페이지로 보정한다.
- 프런트엔드 테스트 140개, 린트, 빌드와 로컬 Chrome 합성 데이터 화면 확인을 수행했다. 11건을 5/5/1건으로 나누는 이동, 상세에서 목록 복귀, 목록별 독립 이동, 분류 변경, 채용 자동 갱신으로 목록 축소, 안건 조회 실패 후 재시도, 모바일 가로 넘침 여부를 확인했다.
- 프런트엔드 변경이며 DB 마이그레이션은 없다.
