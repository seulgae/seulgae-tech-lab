# 사운드 시스템

> 작성일: 2026-11-17

슬개기술연구소의 배경음악(BGM), 환경음(Ambient), 효과음(SFX) 구조와 음원 출처를 정리한다.

## 음원 출처와 라이선스

**모든 소리는 이 저장소의 코드(`frontend/src/audio/synth.ts`)가 브라우저에서 직접 합성한다.** 외부 음원 파일을 내려받거나 저장소에 넣지 않았다.

| 구분 | 만든 방법 | 제작 | 라이선스 |
|---|---|---|---|
| 배경음악 6곡(방별) | 화음 진행·베이스·드럼·멜로디를 사인/삼각파, 일렉트릭 피아노·벨 배음, 카플러스-스트롱 현 뜯기로 합성 | 슬개기술연구소(코드로 생성) | 이 저장소와 동일 |
| 환경음 7종 | 걸러 낸 잡음(갈색·백색), 저음 험, 짧은 클릭·지저귐·귀뚜라미 합성 | 슬개기술연구소(코드로 생성) | 이 저장소와 동일 |
| 효과음 29종 | 잡음 덩어리·주파수 미끄럼·배음 벨 합성 | 슬개기술연구소(코드로 생성) | 이 저장소와 동일 |

- 상용 게임 음악·효과음이나 출처가 불명확한 음원은 쓰지 않았다.
- Kenney·OpenGameArt·Freesound(CC0) 같은 외부 음원을 쓰지 않고 합성을 택했다.
  - 파일을 내려받으려면 매번 사용자 확인이 필요하다.
  - 합성음은 라이선스 문제가 없다.
  - 다운로드 용량도 0이다.
- 나중에 외부 음원으로 바꾼다면 `AudioManager.ensure`가 합성 대신 파일을 읽게 바꾸고, 이 표에 출처·제작자·라이선스를 추가한다.

## 구조

```text
frontend/src/audio/
├── audioSettings.ts   설정(볼륨·켜짐), localStorage 저장, 구독
├── synth.ts           음악·환경음·효과음 합성(Phaser 없음, 22,050Hz 모노)
├── soundRules.ts      방별 사운드, 발걸음 판정·바닥 재질, 거리 감쇠
├── AudioManager.ts    Phaser 사운드 매니저로 재생·페이드·동시 재생 제한
├── SoundSettings.tsx  게임 화면 오른쪽 위 설정 창
└── soundSettings.css
```

- **AudioManager**: 게임마다 하나(`AudioManager.for(game)`)다. 방이 바뀌어 장면이 다시 만들어져도 유지된다.
  - 처음 필요할 때 소리를 합성해 `AudioBuffer`로 Phaser 오디오 캐시에 한 번만 넣고, `game.sound.add`로 재생한다. 외부 오디오 라이브러리는 없다.
- **카테고리**: 배경음악·환경음은 반복 채널이고, 효과음은 한 번 재생한 뒤 정리한다. 볼륨은 `전체 × 카테고리 × 소리별 기준값`이다.
- **어디서나 효과음**: `playSfx(key)`, 다른 연구원 위치의 소리는 `playSpatialSfx(key, 위치, 듣는 사람)`. 게임이 없거나 소리가 꺼져 있으면 아무 일도 하지 않는다.

## 방별 음악과 환경음

| 방 | 배경음악 | 환경음 |
|---|---|---|
| 중앙 로비 | 따뜻한 일렉트릭 피아노 로파이(74bpm, Cmaj7–Am7–Dm7–G7, 레코드 잡음) | 조용한 실내 공기 |
| 개발 연구실 | 집중용 전자 아르페지오(84bpm) | 키보드 타이핑 |
| 서버실 | 낮고 차가운 패드와 벨(64bpm) | 서버 팬·전원 험 |
| 회의실 | 잔잔한 재즈 피아노·워킹 베이스·브러시(88bpm) | 벽시계 초침 |
| 관제실 | 차분하고 미래적인 벨·아르페지오(78bpm) | 전자 장비 험과 점검 신호음 |
| 바깥 초원 | 어쿠스틱 기타 아르페지오(70bpm) | 낮: 바람·시냇물·새, 밤(새벽·저녁): 바람·시냇물·귀뚜라미 |

- 방을 옮기면 이전 곡은 0.9초 동안 줄이고, 새 곡은 1.4초 동안 키운다.
  - 같은 곡이면 이어서 재생한다.
  - 빠르게 오가도 이전 소리는 페이드가 끝나면 정리되어 겹치지 않는다.
- 방 이동이 거부되면 장면이 그대로라 음악도 그대로다.
- 날씨 시스템은 아직 없어서 비·바람 효과는 연결하지 않았다. 시간대는 바깥의 밤 환경음에만 쓴다.

## 발걸음과 거리 기반 소리

- 좌표가 실제로 움직인 거리(약 24px)마다 한 발이다.
  - 방향키를 눌러도 벽·가구에 막혀 좌표가 그대로면 소리가 없다.
  - 멈추면 쌓인 거리를 버려서, 멈춘 뒤 한 발이 더 나지 않는다.
  - 서버 보정·방 이동 같은 48px 넘는 순간이동은 무시한다. 프레임마다 소리를 만들지 않는다.
- 다른 연구원 발걸음은 화면에 그려진(보간된) 위치가 움직일 때만 낸다. 그래서 같은 상태 스냅샷이 반복 와도 소리가 겹치지 않는다.
  - 같은 방만 처리한다(다른 방 연구원은 장면에 없다).
  - 볼륨은 거리 320px까지 줄어들고 그 밖은 0이다. 좌우 위치도 반영한다.
  - 동시 재생은 4개로 제한한다.
- 효과음 전체 동시 재생은 8개로 제한한다. 끝난 소리 객체는 바로 정리한다.
- 새 WebSocket 연결이나 서버 요청은 없다. 사운드는 모두 프론트엔드에서 처리한다.

## 설정과 브라우저 정책

- 기본값: 전체 80%, 배경음악 30%, 효과음 60%, 환경음 40%. 전체 음소거, 카테고리별 켜기, 기본값 초기화가 있다.
- 설정은 localStorage(`seulgae.audio.settings`)에 저장한다. 깨진 값은 항목별로 기본값을 쓴다. 바꾸면 재생 중인 소리에 바로 반영한다.
- 자동 재생 정책: Phaser 사운드 매니저가 잠겨 있으면(첫 클릭·터치·키 입력 전) 음악을 시작하지 않는다. 잠금이 풀리면 현재 방 음악을 시작한다. 설정 창에도 안내를 보여 준다.
- Web Audio가 없거나 합성·재생에 실패해도 게임은 그대로 돈다.
- 탭이 백그라운드로 가면 Phaser 기본 동작(`pauseOnBlur`)으로 소리가 멈추고, 돌아오면 이어서 재생한다.

## 개발 중 확인

개발 서버(`npm run dev`)에서는 브라우저 콘솔의 `__labAudio.debug()`로 오디오 컨텍스트 상태, 현재 곡·환경음, 재생 중인 효과음 수를 볼 수 있다. 운영 빌드에는 들어가지 않는다.
