# 방 이동과 방별 멀티플레이어

중앙 로비(`lobby`)를 허브로 개발 연구실(`development-lab`), 서버실(`server-room`), 회의실(`meeting-room`)을 연결한다. 기존 로비 가구와 연구 기록 컴퓨터는 유지하며 바닥·캐릭터·가구 에셋을 재사용한다. 서버 랙과 회의 테이블 등 가구에는 방별 충돌체가 있다. 새 외부 에셋·라이브러리는 추가하지 않았다.

## 공유 맵과 서버 검증

`shared/lobby-world.json`의 `rooms`에 방 이름, 출입구 ID·좌표·목적지, 안전 스폰, 신규 가구를 정의한다. 서버 `LobbyWorld`와 프런트엔드 `rooms.ts`가 같은 파일을 사용한다. 방 스폰은 벽·가구 밖으로 검증한다. 플레이어 속도 200px/s와 발밑 충돌 크기, 대각선 정규화는 유지한다.

방별 위치는 기존 `LobbyRoom` 방문자에 `roomId`, 연결 내 증가하는 `roomEpoch`를 추가해 관리한다. 전체 정원 5명은 유지한다. 클라이언트가 좌표나 목적지 방을 지정하지 않고 현재 방의 출입구 ID만 요청한다. 서버는 현재 방·출입구 존재·거리 56px·방 세대·1초 이동 쿨다운을 확인한다. 정해진 목적지 스폰만 사용한다.

## WebSocket 프로토콜

기존 `/ws/lobby` 연결, 플레이어 ID와 닉네임을 유지한다. 이동 프로토콜 버전 4의 완료 스텝·ACK 방식을 유지하며, welcome의 방 메타데이터가 있는 연결은 아래 확장을 사용한다.

```json
{"type":"room_change","doorId":"lobby-to-development","roomEpoch":0}
```

승인은 `room_changed`에 `selfId`, 목적지 `roomId`, 증가한 `roomEpoch`, 목적지 `players` 스냅샷을 담는다. 스냅샷의 본인 좌표가 서버가 정한 스폰이다. 거부는 `room_error`로 알려주며 소켓을 닫지 않고 기존 방을 유지한다. 응답이 5초간 없으면 모호한 위치 상태를 계속 사용하지 않고 기존 재연결 절차로 복구한다. 재접속 기본 방은 로비다.

새 `move`, `input`, `chat` 요청에는 현재 `roomEpoch`를 포함한다. 이동 시 서버 대기 명령·수신 sequence·처리 ACK·방향·속도를 초기화한다. 클라이언트도 sequence, 송신 묶음, 입력, 마지막 tick과 예측을 초기화한다. 이전 세대 입력은 위치에 적용하지 않는다. A→B→A 재입장도 방 ID뿐 아니라 세대로 구분한다.

상태·입퇴장·실시간 채팅은 같은 방에만 전파하며 수신자의 `roomId`, `roomEpoch`를 붙인다. 상태에는 `totalOnline`도 포함한다. 클라이언트는 다른 방·이전 세대 상태와 채팅을 무시한다. 원격 보간 알고리즘은 유지하고 장면이 바뀔 때 버퍼를 폐기한다.

## 화면과 입력 수명

Phaser 게임과 React가 소유하는 소켓은 재생성하지 않는다. 서버 승인 이후 기존 Scene을 짧게 페이드하고 재시작해 맵·충돌체·캐릭터·말풍선을 교체한다. 컴퓨터보다 출입구를 먼저 선택하므로 E 한 번에 한 대상만 실행한다. 컴퓨터 연구 기록은 로비에서만 활성화한다. 이동 승인 대기 중 키보드·기존 모바일 조작·채팅을 잠근다. 모바일 기능 추가는 없고 기존 조작을 보존한다.

Scene 종료에서 방 구독, UI 이벤트와 물리 이벤트, 원격 캐릭터, 말풍선, 예측 기록을 정리한다. Phaser Physics 플러그인이 먼저 world를 비울 수 있어 원래 World 객체를 보관해 이벤트를 해제한다. 새 Scene은 현재 방 스냅샷을 다시 구독하고 카메라 페이드를 복원한다. 스폰은 문에서 80px 떨어져 있어 즉시 재진입하지 않는다.

현재 방 이름, 방 인원과 전체 인원을 별도로 표시한다. 이동 오류와 대기 상태도 표시한다. React 채팅은 방별 최근 50개를 전환한다. 과거 기록은 패널에만 표시하며 말풍선으로 재생하지 않는다. 중복 메시지 ID와 기존 길이·도배 제한을 유지한다. 전송 제한은 방 이동으로 초기화되지 않는다. PostgreSQL 저장이나 Kafka 전달은 추가하지 않는다.

## 검증과 한계

자동화는 실제 서버 이동으로 세 연구실을 각각 로비와 반복 왕복(18회 전환), 잘못된 출입구·거리·쿨다운, 세대 증가·ACK 초기화, 방별 기록·충돌을 검사한다. 실제 로컬 WebSocket에서도 동일 ID의 방 변경, 목적지 스냅샷, 이전 입력 무시, 새 sequence 1 이동, 채팅 격리를 확인한다. 프런트엔드는 이전 방 상태·기록 무시, 한 소켓 유지, 중복 요청 방지와 예측 sequence 초기화, 네 방 스폰 충돌을 검사한다. 기존 이동·ACK·원격 보간 회귀 테스트도 유지한다.

로컬 브라우저 두 창에서 로비↔개발 연구실, 로비→서버실, 같은 방 합류 및 채팅 전달, 다른 방 채팅 차단을 확인했다. 방 전환 시 실제 발견한 World 종료 오류는 수정하고 null World 종료 순서 회귀 테스트를 추가했다. 이후 브라우저 도구 연결이 종료되어 최종 UI 변경 이후 회의실의 실제 화면 확인, 장시간 반복 이동·힙 측정은 완료하지 못했다. 회의실 왕복·충돌·스폰은 자동화로 확인한다. 전체 시각적 무진동·메모리 누수 부재를 단정하지 않는다.

## 운영 확인은 사용자 수행

운영 서버 SSH·수동 deploy.sh·DB·Kafka·워크플로 수동 실행·운영 최종 테스트는 수행하지 않는다. 기존 워크플로와 배포 활성화 변수를 변경하지 않는다. 병합 후 자동 배포 및 운영 검증은 사용자가 진행한다.

- 로비↔각 방 여섯 방향 왕복, E 연속 입력과 전환 직후 이동
- 두 방문자의 같은/다른 방 캐릭터·입퇴장·전체 및 방별 인원
- 같은 방 채팅·말풍선, 다른 방 미전달, 재입장 기록과 중복 말풍선 부재
- 채팅 포커스 중 이동 잠금, 로비 연구 기록 E·닫기·API
- 실제 네트워크 지연에서 이동 보정·방 전환 진동 및 재연결
- 장시간 반복 전환의 메모리·이벤트 리스너 증가 여부
