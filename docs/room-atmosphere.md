# 방별 분위기 리디자인

네 방이 각자의 색·재질·조명·이벤트를 갖도록 화면을 다시 만들었다. **충돌과 이동은 바꾸지 않았다.** 가구의 위치와 충돌 크기는 서버와 공유하는 `shared/lobby-world.json` 그대로이고, 클라이언트가 같은 크기의 다른 텍스처로 바꿔 그린다. 서버·프로토콜 변경은 없다.

| 방 | 분위기 | 주요 장식 |
|---|---|---|
| 중앙 로비 | 따뜻한 대리석, 레드 카펫, 금색 몰딩의 호텔식 로비 | 창문, 샹들리에, 안내판, 안내 데스크·벨, 책장, 소파, 키오스크 |
| 개발 연구실 | 어두운 네이비 바닥 격자와 네온 그린·시안 | CI 벽 스크린, 코드가 흐르는 벽 패널, 듀얼 모니터 책상, 오실로스코프 작업대, 네온 케이블 바닥 |
| 서버실 | 차가운 파란 조명, 이중 바닥, 경고 줄무늬 | 메시 문 랙과 깜빡이는 LED, 냉복도 통풍 타일과 냉기 파티클, 냉각기(CRAC), 경광등 |
| 회의실 | 원목 마루, 세이지 카펫, 크림 벽 | 원목 회의 테이블(노트북·커피), 화이트보드 안건, 실제 시각의 벽시계, 창문, 회의 표시등 |

React 페이지도 같은 팔레트를 따른다. `App`이 `document.documentElement`에 `--room-background/card/border/accent/muted` 변수를 설정하고, 페이지 배경·게임 카드·채팅창·상태줄·키 표시·모바일 조작부가 이 변수를 쓴다. 오른쪽 안내 문구도 방마다 바뀐다.

## 구조

- `game/rooms/roomThemes.ts`: 방별 팔레트(바닥·벽·문·페이지), 카메라·조명 색, 가구 텍스처 교체표, 바닥 배치 `floorData()`, 안내 문구. Phaser에 의존하지 않는다.
- `game/assets/roomAssets.ts`: 방별 바닥 3프레임·벽·문틀·문짝과 교체 가구, 조명(`glow`)·파티클 텍스처. 기존처럼 정수 좌표 `fillRect`만 쓴다. 교체 가구는 원래 텍스처와 크기가 같다(테스트로 확인).
- `game/LobbyMap.ts`: 테마 바닥·벽, 가구 그림자, 교체 텍스처, 강조 테두리 색.
- `game/rooms/DoorAnimator.ts`: 출입구 문 열림·닫힘.
- `game/rooms/RoomFx.ts`: 방별 장식과 이벤트, 상단 안내 배너.
- `game/rooms/roomEventLogic.ts`: 이벤트 간격, 문구 순환, 도착 감지, CI 빌드, 서버 경보 상태. Phaser에 의존하지 않는다.

## 문 애니메이션

문틀 안에 문짝 두 장이 있고, 경첩 쪽을 기준으로 가로 배율을 줄여 안쪽으로 열린다. 열리면 문 너머로 **목적지 방의 조명 색**이 비친다.

1. 출입구에서 E를 누르면 `changeRoom`이 요청을 보낸 즉시 문이 열리기 시작한다(280ms).
2. 서버 승인이 먼저 와도 문이 다 열릴 때까지 기다린 뒤 200ms 페이드하고 Scene을 `{ from }`으로 재시작한다.
3. 도착한 방에서는 지나온 문이 열린 채로 시작해 220ms 뒤 닫힌다.
4. 거부되거나 응답 시간이 초과돼 같은 방에 남으면 문을 다시 닫는다.

서버 이동 검증, 쿨다운, 5초 응답 제한은 그대로다. 문은 아래쪽 벽에 있으므로 캐릭터가 항상 문 앞에 그려지도록 낮은 깊이를 쓴다.

## 방별 이벤트

이벤트는 **각 브라우저에서만 재생되는 연출**이다. 서버 상태를 바꾸지 않고 다른 참가자와 동기화하지도 않는다. 타이머·트윈은 Scene 종료 시 함께 정리된다.

- **로비**
  - 입장할 때 환영 배너가 나온다.
  - 안내판 문구가 5초마다 바뀐다.
  - 35~55초마다 안내 방송 배너와 함께 샹들리에에서 반짝이가 흩어진다.
  - 다른 연구원이 로비에 들어오면 "OO 님이 로비에 도착했어요" 배너와 함께 그 위치에 반짝이가 나온다. 첫 스냅샷의 기존 인원과 본인은 제외한다.
- **개발 연구실**
  - 벽 패널 코드가 0.42초마다 흐른다.
  - 3초 뒤부터 20~32초마다 CI 빌드가 돈다. 진행 막대가 4.2초 동안 찬 뒤 결과가 나온다.
    - 성공(약 78%): 녹색 표시, 색종이, 성공 배너.
    - 실패: 빨간 화면 깜빡임, 짧은 화면 흔들림, 실패한 테스트 수 배너.
  - 책상 컴퓨터 E는 기존 실제 빌드 정보 패널이다.
- **서버실**
  - LED가 항상 깜빡이고 냉복도에서 냉기가 올라온다.
  - 8초 뒤부터 28~45초마다 한 랙에 과열 경보가 울린다. 랙이 붉게 빛나고 경광등이 깜빡이며, 표시판 온도가 31°C로 오르고 냉기가 약해진다.
  - 경보 중에는 랙 안내가 "E · 냉각 시스템 가동"으로 바뀐다. E를 누르면 상태 패널 대신 냉기 폭발과 함께 경보가 해제된다.
  - 12초 안에 대응하지 않으면 자동으로 냉각된다.
  - 경보가 없을 때 랙 E는 기존 실시간 서버 상태 패널이다.
- **회의실**
  - 벽시계는 실제 시각을 가리킨다. 화이트보드 안건은 9초마다 바뀌고 커피잔에서 김이 오른다.
  - 테이블 대화를 켜면 회의 모드가 된다. 방이 어두워지고 테이블에 스포트라이트가 들어오며, 표시등이 "● 회의 중"으로 바뀌고 배너가 뜬다. 끄거나 테이블을 떠나면 원래대로 돌아온다.

## 글자 렌더링 (한글 깨짐 수정)

증상: 이름표·문 이름·배너 같은 캔버스 속 한글의 획이 끊기거나 뭉개졌다.

원인: 세 가지가 겹쳤다. (실측: 564 CSS px × DPR 1.25 = 705 기기 픽셀)

1. 게임 캔버스를 항상 800×600으로 그린 뒤 CSS로 705 기기 픽셀까지 줄였다. 이때 `image-rendering: pixelated`(최근접)가 픽셀 줄의 약 12%를 버려 1px짜리 한글 획이 사라졌다.
2. `pixelArt: true`이면 글자 텍스처도 최근접 필터를 쓴다. 해상도 2로 만든 글자를 800 캔버스로 줄이는 단계에서 같은 손실이 한 번 더 생겼다.
3. 글꼴로 `monospace`·`Arial`을 지정해 한글은 임의 대체 글꼴로 그려졌다. 일부 글자는 9~10px로 너무 작았다.

수정: `game/render/renderScale.ts`

- **캔버스 크기**: 내부 해상도를 `표시 너비 × DPR`에 맞춘다. 배율은 0.5~3이다. 세계 좌표는 계속 800×600이고 카메라 줌이 배율만큼 확대·축소하므로, 서버 충돌·이동·좌표 계산은 그대로다.
- **크기 변경**: `GameCanvas`가 컨테이너 크기 변화를 감지해 `game.scale.resize`를 호출한다. Scene은 `resize` 이벤트를 받아 카메라 줌을 다시 맞추고, 컨테이너 안을 포함한 모든 글자의 해상도를 갱신한다.
- **글자**: 모든 캔버스 글자를 `crispText`로 만든다. 해상도가 렌더 배율과 같아서 기기 픽셀과 1:1로 그려진다.
- **글꼴**: 한글은 `UI_FONT`(맑은 고딕, Apple SD Gothic Neo, Noto Sans KR 순), 영문·숫자 표시는 `MONO_FONT`를 쓴다. 한글 글자는 최소 11~12px로 키웠다.
- **CSS**: 캔버스 CSS는 `image-rendering: auto`로 둔다. 1:1이라 브라우저가 다시 샘플링할 일이 없다. 픽셀아트 텍스처는 계속 Phaser가 최근접으로 확대한다.

검증:

- `tests/render-scale.test.mjs`: 배율 계산, 4:3 정수 캔버스, 글자 해상도, 크기 변경 시 컨테이너 안 글자 갱신.
- 로컬 브라우저(1024px 창, DPR 1.25): 캔버스가 705×529로 만들어져 기기 픽셀과 1:1로 표시되고, 이름표·문 이름의 한글이 끊기지 않는 것을 확인했다.
- 모바일 폭은 브라우저 창이 숨겨져 렌더링이 멈춘 탓에 화면으로 확인하지 못했다.
